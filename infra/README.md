# Infrastructure Directory

This directory contains Terraform configuration files and Lambda deployment packages for the Customer Management MVP.

## Contents

### Terraform Configuration Files

- `main.tf` - Main resource definitions (DynamoDB, Lambda, API Gateway, Cognito)
- `variables.tf` - Input variable declarations
- `outputs.tf` - Output value definitions
- `providers.tf` - AWS provider configuration
- `versions.tf` - Terraform and provider version constraints
- `terraform.tfvars` - Default variable values

### Environment-Specific Configuration

- `envs/dev.tfvars` - Development environment variables
- `envs/prod.tfvars` - Production environment variables

### Lambda Deployment Packages

- `authorizer.zip` - Lambda Authorizer deployment package (~22 MB)
- `crud.zip` - Customer CRUD Lambda deployment package (~16 MB)

**Note:** These zip files are generated by the build scripts and should not be committed to version control.

## Quick Start

### 1. Build Lambda Packages

From the project root directory, run one of the build scripts:

```bash
# Python script (recommended - cross-platform)
python build_lambdas.py

# Bash script (Linux/macOS)
./build_lambdas.sh

# Batch script (Windows)
build_lambdas.bat
```

This will create `authorizer.zip` and `crud.zip` in this directory.

### 2. Initialize Terraform

```bash
cd infra
terraform init
```

### 3. Deploy Infrastructure

**Development Environment:**
```bash
terraform plan -var-file="envs/dev.tfvars"
terraform apply -var-file="envs/dev.tfvars"
```

**Production Environment:**
```bash
terraform plan -var-file="envs/prod.tfvars"
terraform apply -var-file="envs/prod.tfvars"
```

### 4. View Outputs

After successful deployment:

```bash
terraform output
```

This will display:
- `api_endpoint` - API Gateway endpoint URL
- `user_pool_id` - Cognito User Pool ID
- `dynamodb_table_name` - DynamoDB table name

## Common Operations

### Update Lambda Code

When you modify Lambda function code:

```bash

cd ..
python build_lambdas.py

# Apply changes
cd infra
terraform apply -var-file="envs/dev.tfvars"
```

### View Current State

```bash
terraform show
```

### List All Resources

```bash
terraform state list
```

### Destroy Infrastructure

**Warning:** This will permanently delete all resources and data.

```bash
terraform destroy -var-file="envs/dev.tfvars"
```

## Terraform State

Terraform maintains state in `terraform.tfstate` (local backend). For production use, consider:

1. **Remote Backend**: Store state in S3 with DynamoDB locking
2. **State Encryption**: Enable encryption at rest
3. **State Versioning**: Enable S3 versioning for state recovery

Example remote backend configuration:

```hcl
terraform {
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "customer-management/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    dynamodb_table = "terraform-state-lock"
  }
}
```

## Environment Variables

Terraform uses these environment variables (if set):

- `AWS_PROFILE` - AWS CLI profile to use

- `AWS_ACCESS_KEY_ID` - AWS access key
- `AWS_SECRET_ACCESS_KEY` - AWS secret key

## Troubleshooting

### Error: "No such file or directory: authorizer.zip"

**Solution:** Run the build script from the project root:
```bash
cd ..
python build_lambdas.py
cd infra
```

### Error: "Error acquiring the state lock"

**Solution:** Another Terraform process is running. Wait for it to complete or:
```bash
terraform force-unlock <lock-id>
```

### Error: "Provider configuration not present"

**Solution:** Initialize Terraform:
```bash
terraform init
```

### Error: "Insufficient permissions"

**Solution:** Verify AWS credentials have necessary IAM permissions:
```bash
aws sts get-caller-identity
```

## Resource Naming

Resources follow this naming convention:
- Lambda Functions: `customer-management-{function-name}`
- API Gateway: `customer-management-api`
- DynamoDB Table: `customers`
- Cognito User Pool: `customer-management-users`
- CloudWatch Log Groups: `/aws/lambda/customer-management-{function-name}`

## Security Notes

1. **State Files**: Contain sensitive data. Never commit to version control.
2. **Variables**: Use environment-specific tfvars for sensitive values.
3. **IAM Roles**: Follow least privilege principle.
4. **Encryption**: Enable encryption for DynamoDB and CloudWatch Logs.
